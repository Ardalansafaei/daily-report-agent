# راهنمای گزارش روزانه

مرجع شمارش و تعریف‌ها. دستورهای اجرا در `AGENTS.md` است.

## منبع داده

تنها منبع: رخدادهای گیت‌لب برای صاحب توکن، از راه `tools/gitlab.ps1`.

روش: صفحات رخداد یکی‌یکی خوانده می‌شود تا صفحه‌ای برسد که قدیمی‌ترین رخدادش قبل از شروع بازه است. بعد رخدادها بر اساس دو شرط صاف می‌شوند: نویسنده من باشد و زمان رخداد داخل بازه باشد. بازه‌ی پیش‌فرض ۰۵:۰۰ تا ۲۴:۰۰ به وقت تهران روی تاریخ خواسته‌شده است. `24:00` تا آخر همان تاریخ است و نیمه‌شب روز بعد را شامل نمی‌شود.

## بخش ۱ — اسناد بررسی‌شده

هر رخداد «کامنت روی صفحه‌ی ویکی» که متنش نشانه‌ی یوزراستوری داشته باشد.

- کلید یکتاسازی: خود صفحه.
- «جمع سند»: تعداد صفحه‌های یکتا. «جمع نظر»: تعداد کامنت‌ها.
- عنوان: مقدار فیلد «عنوان» در کامنت؛ اگر نبود، نام صفحه.

## بخش ۲ — APIهای تست‌شده

هر رخداد «کامنت روی صفحه‌ی ویکی» که متنش نشانه‌ی سند API داشته باشد.

- کلید یکتاسازی: متد و مسیر، بدون توجه به بزرگی و کوچکی حروف.
- «جمع اندپوینت»: تعداد کلیدهای یکتا. «جمع نظر»: تعداد کامنت‌ها.
- نمایش: نام سرویس و بعد `METHOD /path`. اگر مسیر نبود، فقط متد می‌آید.

هر کامنت سند API یعنی همان اندپوینت بررسی و تست شده است؛ پس تعداد نظر می‌تواند از تعداد اندپوینت بیشتر باشد (مثلاً وقتی همان بررسی در چند ترد تکرار شده یا در چند روز بازبینی شده است).

## بخش ۳ — ایشوهای ثبت‌شده

رخداد «ساختن» روی Issue یا WorkItem در پروژه‌ی `superuni/development/tasks/kouleh`.

- کلید یکتاسازی: شماره‌ی ایشو. عنوان از خود رخداد.

## بخش ۴ — ایشوهای بررسی‌شده

رخدادهای زیر روی ایشوها، همه با نویسنده‌ی من:

- کامنت روی ایشو.
- بستن یا بازکردن دوباره‌ی ایشو.

- کلید یکتاسازی: شماره‌ی ایشو.
- «جمع»: تعداد ایشوهای یکتا.
- وضعیت: وضعیت فعلی ایشو در گیت‌لب، نه وضعیت لحظه‌ی بررسی. با یک درخواست دسته‌ای گرفته می‌شود و اگر ایشویی در آن نبود، با `issue-get` جداگانه.
- اگر ایشویی را امروز ساخته و امروز هم بررسی کرده باشم، در هر دو بخش می‌آید.

## محدودیت‌ها

- فقط رخدادهای گیت‌لب دیده می‌شود. کارهایی مثل تست API روی استیج، بررسی SQL، مطالعه‌ی سند یا جابه‌جایی فایل اگر رخداد گیت‌لب نداشته باشد، در گزارش نمی‌آید.
- کامنت‌هایی که متنشان نشانه‌ی هیچ‌کدام از دو قالب نباشد (مثلاً یک پاسخ کوتاه) در بخش‌های ۱ و ۲ شمرده نمی‌شوند.
- رخدادهای گیت‌لب سقف زمانی نگه‌داری دارند. برای تاریخ‌های خیلی قدیمی ممکن است داده‌ای نمانده باشد.
- اگر اسکریپت با پیام `[warn]` تمام شود، یعنی قبل از رسیدن به شروع بازه سقف صفحات پر شده و گزارش ممکن است ناقص باشد؛ همان را به من بگو.
- شماره‌ی نسخه‌ی ویکی، وضعیت کاتالوگ و لینک هر کامنت در این گزارش نمی‌آید؛ این گزارش شمارشی است.

## خلاصه

بعد از خط بازه و قبل از چهار بخش، یک «خلاصه» می‌آید. هر ردیفش همان جمع بخش متناظر است. جمع تازه‌ای حساب نمی‌شود.

## نمونه

```markdown
# گزارش روزانه - 2026-11-03

بازه: 05:00 تا 24:00 به وقت تهران

## خلاصه
- اسناد: 5 سند - 5 نظر
- API: 54 اندپوینت - 61 نظر
- ایشوهای ثبت‌شده: 8 ایشو
- ایشوهای بررسی‌شده: 13 ایشو
```

## عیب‌یابی

| نشانه | معنی | کار |
|---|---|---|
| `gitlab.ps1 ... failed: HTTP 401` | توکن نامعتبر است | بگو توکن `.env` مشکل دارد؛ خودت تغییرش نده |
| `transport failure` | شبکه یا پروکسی | یک بار دیگر اجرا کن؛ ابزار خودش از پروکسی استفاده می‌کند |
| `[warn] issue state unknown` | وضعیت یک ایشو گرفته نشد | همان ایشو با وضعیت «نامشخص» چاپ می‌شود |
| `[warn] stopped after N event pages` | سقف صفحات | گزارش ممکن است ناقص باشد؛ به من بگو |
